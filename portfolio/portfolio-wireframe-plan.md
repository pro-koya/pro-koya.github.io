# ポートフォリオサイト ワイヤー案

## 目的

- トップページで「何ができる人か」をすぐ伝える
- 実績を主役にしつつ、説明過多にならない構成にする
- 実績追加時にトップ・カテゴリ・詳細の関係が崩れないようにする

---

## 情報設計の基本方針

### 1. トップページの役割

- 第一印象で「依頼できる領域」を伝える
- 注目実績を2〜3件見せる
- 詳しい説明はカテゴリページ・詳細ページに逃がす
- 相談導線は常に迷わない位置に置く

### 2. カテゴリページの役割

- そのカテゴリで何を任せられるかを整理する
- 実績一覧を並べる
- 共通する強みを短く補足する

### 3. 実績詳細ページの役割

- その実績で何を作ったか
- 何が難しかったか
- 何を任せられそうか

---

## トップページ ワイヤー案

### ねらい

- 参考サイトのように、余白と視線の流れで見せる
- 今の `About / Services / Works / Process / Tech Stack / Notes` を圧縮する
- 最初の3スクロール以内で判断材料が揃う状態にする

### セクション構成

#### 1. Header

```text
+-----------------------------------------------------------+
| koya                          Works / About / Contact 相談 |
+-----------------------------------------------------------+
```

- メニューは3項目で十分
- CTAは1つだけ強く見せる

#### 2. Hero

```text
+-----------------------------------------------------------+
| What I Do                                                 |
| 設計から伴走する                                          |
| Webアプリ開発の技術パートナー                             |
|                                                           |
| 要件整理、設計、実装、改善まで一貫して対応。              |
| 業務システムやWebアプリを中心に、使い続けられる構成を作る |
|                                                           |
| [実績を見る]  [相談する]                                  |
|                                                           |
| Next.js / React / Node.js / PostgreSQL                    |
+-----------------------------------------------------------+
```

#### 文言の方向性

- 見出しは2〜3行で止める
- リード文は2文まで
- チップは4個以内
- メトリクスやダイアグラムはヒーローから外す

#### 3. Featured Works

```text
+---------------------------+-------------------------------+
| 注目実績 01               | 注目実績 02                   |
| セッツマルシェ            | Liftly                        |
| 食材EC + 業務システム     | 継続しやすい筋トレ記録アプリ   |
| [詳細を見る]              | [詳細を見る]                  |
+---------------------------+-------------------------------+
```

- カテゴリより先に実績を置く
- 1件につき、説明は1行 + タグ3個まで
- ここで「作れるものの実感」を作る

#### 4. What I Do

```text
+-------------------+-------------------+-------------------+
| 要件整理          | Webアプリ開発     | 業務改善・自動化   |
| 曖昧な相談を整理   | 運用前提で設計実装 | 継続しやすく整える |
+-------------------+-------------------+-------------------+
```

- 今の `services` を3項目に圧縮
- DB設計は `要件整理` か `Webアプリ開発` に吸収
- AI活用は独立見出しではなく補足文に入れる

#### 5. About / Style

```text
+-----------------------------------------------------------+
| About                                                     |
| 最小コストで成果を出すために、                            |
| 作る前の整理を大切にしています。                          |
|                                                           |
| - 要件の言語化から入れる                                  |
| - 運用と拡張を見据えて組み立てる                          |
| - 速さと品質のバランスを取る                              |
+-----------------------------------------------------------+
```

- 今の `About` と `Process` の要点だけを統合
- 仕事の価値観を短く伝える場所
- 趣味要素を入れるなら最下部に1行だけで十分

#### 6. Contact

```text
+-----------------------------------------------------------+
| 相談の入口はランサーズにまとめています                    |
| 要件が固まりきっていない段階でも大丈夫です                |
| [ランサーズで相談する]                                    |
+-----------------------------------------------------------+
```

- 画像はなくても成立する
- 最後は迷わせず1アクションにする

```text

3. Featured Works
4. What I Do
5. About / Style
```

- Hero内の `Delivery Map`

- 独立した `Notes`

### 残し方を変える候補

- 技術スタックは Hero の小さなチップへ
- 趣味は About の末尾に短文で入れる
- カテゴリ紹介は Featured Works の下に小さく置く

## カテゴリページ ワイヤー案

### 目的

- そのカテゴリで受けられる相談内容を整理する
- 実績が増えても一覧として機能する

### 構成

#### 1. Category Hero

```text
+-----------------------------------------------------------+
| Category / Web Apps                                       |
| Webアプリ開発・業務システム開発                           |
|                                                           |
| 会員機能、管理画面、決済、権限設計など                    |
| 運用前提のプロダクト開発をまとめています                  |
+-----------------------------------------------------------+
```

- ヒーローはもっと軽くする
- 画像はあっても1枚だけ
- サマリーカードは削ってよい

#### 2. Works List

```text
+-----------------------------------------------------------+
| Works in This Category                                    |
|                                                           |
| [thumbnail] セッツマルシェ                                |
| 食材EC + B2B業務要件まで含むプラットフォーム             |
| Express / PostgreSQL / Stripe                             |
| [詳細を見る]                                              |
|                                                           |
| [thumbnail] 次の実績                                      |
| 要約                                                      |
| タグ                                                      |
| [詳細を見る]                                              |
+-----------------------------------------------------------+
```

- 今後増えても同じカードを足すだけにする
- カテゴリページでは「一覧性」を優先

#### 3. Category Contact CTA

```text
+-----------------------------------------------------------+
| このカテゴリに近い相談があれば、ご相談ください            |
| [相談する]                                                |
+-----------------------------------------------------------+
```

## デザインの方向性

### 参考サイトから取り入れたい点

- 1画面目で言いたいことが明快
- 余白が広く、読ませすぎない
- カードを増やしすぎず、文字の強弱で見せる
- 作品や本人像が静かに伝わる

### 現サイトから調整したい点

- ガラス感、装飾、情報カードがやや多い
- セクションごとの役割が少し重なっている
- 「丁寧な説明」が「情報量の多さ」に見えやすい

### デザイントーン案

- 背景は今より静かにする
- グリッドの主張を弱める
- Heroは1枚の大きな面で見せる
- カードは必要最小限にする
- 見出しは太さと余白で強弱をつける

---

## 文言の粒度ルール

- Hero本文は2文まで
- 実績カードの説明は1〜2行まで
- タグは3〜4個まで
- 1セクションにつき主メッセージは1つだけ
- 「似た意味の説明」は別セクションに分けない

---

## 実装に移しやすい構成案

### データ構造

- 実績データを1ファイルに集約する
- トップの注目実績、カテゴリ一覧、詳細導線を同じデータから作る

```text
docs/
├─ index.html
├─ categories/
├─ case-studies/
├─ assets/
└─ data/
   └─ works.js
```

### 1件あたりの最低項目

- `slug`
- `title`
- `category`
- `summary`
- `tags`
- `thumbnail`
- `featured`
- `detailUrl`

### 更新フロー

1. 実績データを1件追加
2. 必要なら画像を追加
3. 詳細ページを1枚追加
4. トップとカテゴリは自動で反映

---

## このワイヤー案をそのまま実装する場合の優先順位

1. トップのセクションを6つに圧縮する
2. Featured Works をトップの主役に置く
3. カテゴリページを「一覧ページ」として軽くする
4. 実績データを共通化する
5. 見た目の装飾を少し引いて余白を増やす

---
